# S9 问题收口与 GEO 业务建议框架

本文档定义 S9 业务赋能规划师的方法论。S9 的职责不是输出旧版固定赋能菜单，而是把 S1-S8 的策略成果收束为企业问题、GEO 影响与优先行动建议。

---

## 一、策略收口框架

S1-S8 分别回答了企业“事实是什么、用户是谁、趋势是什么、品牌站在哪里、AI 如何呈现品牌、品牌怎么说、品牌怎么看起来、品牌该回答什么”。S9 要把这些分散结论转译为企业可理解的业务问题和 GEO 行动建议。

| 策略层输出 | S9 需要判断的问题 | S9 转译动作 |
| :--- | :--- | :--- |
| S1 品牌事实 | 企业是否有可被 AI 引用的事实、资质、案例与证明 | 提炼实体事实与证据链缺口 |
| S2 营销图谱 | 用户真实问题是否被内容和页面承接 | 提炼意图承接缺口 |
| S3 品类趋势 | 趋势机会是否被品牌叙事占位 | 提炼趋势占位与品类词机会 |
| S4 定位声明 | 定位是否清晰、可信、有差异 | 提炼定位与 RTB 问题 |
| S5 品牌诊断 | AI 回答是否能提及、理解、推荐品牌 | 提炼 AI 可见性、信源和竞品占位问题 |
| S5.5 语义审计 | 语义资产是否稳定、机器可读 | 提炼实体识别和语义一致性问题 |
| S6 话语体系 | 品牌语言是否可被标准答案复用 | 提炼话语模块化和一致性问题 |
| S7/S8 视觉与问答 | 视觉、问题路径、内容与落地页是否形成闭环 | 提炼问答资产和页面承接问题 |

---

## 二、完整性检查体系

S9 的完整性检查不是为了判断是否可以输出旧模块，而是为了确认问题总结和建议是否具备证据基础。

| 维度 | 检查内容 | 严重程度 | 处理方式 |
| :--- | :--- | :--- | :--- |
| 文件完整性 | S1-S8 关键文件是否存在、是否可解析 | 阻断级 | 缺少核心文件时要求补齐或标注无法判断 |
| 证据链完整性 | 企业问题是否能回溯到 S1-S8 的具体文件 | 阻断级 | 无证据的问题不得写入结论 |
| 逻辑一致性 | S4 定位、S6 话语、S8 答案是否一致 | 警告级或阻断级 | 作为问题写入建议包 |
| S5 样本口径 | AI 监测覆盖的问题数、平台数、回答数 | 非阻断级 | 按实际样本分析，写明置信度，不得判定“数据不完全” |
| 官网/结构化数据建议 | 官网是否能承接 S8 问题路径和 GEO 结构化要求 | 业务判断 | 写入 `GEO_A5_site_schema` 行动建议，供 E5 信源建设清单或外部官网改造团队使用 |

---

## 三、问题诊断矩阵

S9 应使用统一问题矩阵组织结论。问题编号使用 `P-01`、`P-02`、`P-03` 等格式。

| 字段 | 说明 |
| :--- | :--- |
| 问题编号 | `P-XX` |
| 企业问题 | 用业务语言说明问题本身 |
| 证据来源 | 指明来自 S1-S8 的哪些文件或结论 |
| 业务影响 | 说明对获客、信任、转化、品牌一致性的影响 |
| GEO 影响 | 说明对 AI 识别、引用、排名、推荐和信源的影响 |
| 严重程度 | 高、中、低 |
| 置信度 | 高、中、低；若 S5 为部分样本，应适当标注样本边界 |

---

## 四、GEO 行动建议体系

S9 使用 `recommended_business_actions` 输出优先行动。每项行动应链接到一个或多个问题，并说明推荐原因与预期业务效果。

| action_id | 行动名称 | 优先级判断 |
| :--- | :--- | :--- |
| `GEO_A1_entity_facts` | 实体与事实资产修复 | 当企业事实、资质、案例、服务边界和 RTB 证据不足时优先 |
| `GEO_A2_ai_visibility` | AI 可见性修复 | 当 S5 显示提及率低、排名靠后、情绪弱或竞品占位时优先 |
| `GEO_A3_qa_assets` | 问答内容资产建设 | 当 S2/S8 显示高意图问题未被承接时优先 |
| `GEO_A4_positioning_language` | 定位与话语一致性 | 当 S4/S6/S8 存在表达断裂时优先 |
| `GEO_A5_site_schema` | 网站与结构化数据 | 当官网无法承接问题路径或 Schema 缺失时优先 |
| `GEO_A6_distribution_citations` | 分发与引用路径 | 当 S5 显示信源缺口或竞品引用占位明显时优先 |

---

## 五、执行路线图设计

S9 可以提供 4-12 周的行动节奏，但路线图必须服务于 GEO 问题修复，而不是泛化为运营日历或 KPI 看板。

| 阶段 | 建议重点 | 典型行动 |
| :--- | :--- | :--- |
| 第 1 阶段 | 修复基础实体与证据 | `GEO_A1_entity_facts`、`GEO_A4_positioning_language` |
| 第 2 阶段 | 补齐高意图问答内容 | `GEO_A3_qa_assets`、`GEO_A5_site_schema` |
| 第 3 阶段 | 提升 AI 可见性与引用来源 | `GEO_A2_ai_visibility`、`GEO_A6_distribution_citations` |
| 第 4 阶段 | 复测与迭代 | 重新运行 S5，比较提及率、排名、情绪和信源变化 |

## 六、风险管理

| 风险 | 影响 | S9 处理方式 |
| :--- | :--- | :--- |
| 客户基础事实不足 | GEO 建议缺少证据支撑 | 将“事实资产不足”列为问题，而不是编造证明 |
| S5 样本较少 | 结论置信度有限 | 按实际样本分析，标注样本边界，建议后续扩样复测 |
| 官网承接能力弱 | 内容和问答资产难以被稳定抓取 | 评估是否需要官网/Schema 改造，并写入 E5 信源建设清单或外部官网改造建议 |
| 话语与定位不一致 | AI 回答容易失真 | 建议先修正 S4/S6/S8 的表达一致性 |
| 信源被竞品占位 | AI 推荐可能偏向竞品 | 建议布局高权重第三方信源和可引用页面 |

---

## 七、禁止事项

S9 禁止继续输出旧版固定板块。尤其不得把与 S1-S8 证据链无关的泛化运营事项作为 S9 的固定角色。若这些内容在特殊项目中确有必要，只能作为后续人工延展，不属于本 Workflow 的 S9 默认产物。
