# S9 问题总结与 GEO 业务建议体系

本文档定义 S9 业务赋能规划师的新职责边界。S9 不再输出固定赋能菜单，也不再让用户勾选预设运营板块。S9 的核心任务是基于 S1-S8 的全部策略产出，综合判断企业当前最明显的问题，并把这些问题转译为 GEO 业务增长建议。

---

## 1. S9 的新角色

S9 是策略层的**问题收口与 GEO 建议节点**。它不是执行层任务分发器，也不是泛营销咨询菜单生成器。它必须回答三个问题：第一，S1-S8 已经暴露出企业哪些明显问题；第二，这些问题会如何影响企业在生成式 AI、搜索、内容信任与转化路径中的表现；第三，企业下一步应优先做哪些 GEO 业务动作。

| 旧角色 | 新角色 |
| :--- | :--- |
| 生成固定赋能菜单 | 总结 S1-S8 暴露的企业问题 |
| 让客户选择预设板块 | 由 S9 直接判断优先业务动作 |
| 泛运营建议 | GEO 业务建议 |
| 与策略证据无关的默认模块 | 删除，不再作为 S9 默认输出 |
| 模块菜单 | `recommended_business_actions` 行动清单 |

---

## 2. 问题归因框架

S9 必须把 S1-S8 的发现归纳为“企业问题”，而不是只复述每个节点的产物。每个问题必须至少有一个明确来源，最好形成跨节点证据链。

| 问题类型 | 常见表现 | 主要来源 | GEO 影响 |
| :--- | :--- | :--- | :--- |
| 实体事实薄弱 | 企业介绍、产品能力、资质、案例、服务边界缺少结构化证据 | S1、S4、S5.5 | AI 难以准确识别企业实体，生成回答容易泛化或遗漏品牌 |
| 意图承接不足 | 用户真实问题未被品牌内容回答，负面疑虑缺少标准回应 | S2、S8、S6 | AI 更容易引用竞品、论坛或第三方替代答案 |
| 趋势占位缺口 | 品类增长方向与品牌当前表达不一致 | S3、S4、S8 | 品牌无法在新兴问题和品类词中形成默认答案 |
| 定位证据断裂 | 定位有主张但缺少 RTB、案例和可引用证明 | S4、S1、S5 | AI 回答可能提及品牌但不推荐，或推荐理由偏弱 |
| AI 可见性弱 | 提及率低、排名靠后、情绪弱、竞品更常占位 | S5 | 生成式搜索中的曝光、信任和转化机会下降 |
| 语义资产不稳定 | 名称、品类、能力、差异点在不同文件中表达不一致 | S5.5、S6、S8 | AI 对品牌的实体识别和能力归因不稳定 |
| 话语不可复用 | 卖点语句泛泛，缺少可直接进入答案的模块化表达 | S6、S8 | 内容被 AI 摘取和引用的概率降低 |
| 落地页与结构化数据缺口 | 官网页面无法承接核心问题，Schema 与实体页不足 | S8、S1、S5 | 搜索引擎和生成式引擎缺少可信抓取入口 |
| 信源路径不足 | 自有内容和第三方高权重页面没有形成引用网络 | S5、S8 | AI 回答引用竞品或第三方，品牌难成为信源 |

---

## 3. GEO 业务建议域

S9 的建议必须围绕 GEO 目标展开，即提升企业被 AI 识别、理解、引用、推荐与转化的能力。建议可以涉及内容、官网、信源、话语和页面结构，但不得退回旧版固定模块菜单。

| 建议域 | action_id | 适用问题 | 关键动作 |
| :--- | :--- | :--- | :--- |
| 实体与事实资产修复 | `GEO_A1_entity_facts` | 实体事实薄弱、定位证据断裂、语义资产不稳定 | 补齐企业实体信息、产品/服务事实表、资质证明、案例证据链、可引用素材 |
| AI 可见性修复 | `GEO_A2_ai_visibility` | AI 提及率低、排名靠后、竞品占位、情绪偏弱 | 根据 S5 诊断补强高优先级问题、竞品差距和 AI 引用场景 |
| 问答内容资产建设 | `GEO_A3_qa_assets` | 用户意图承接不足、负面疑虑未回应、话语不可复用 | 建设 FAQ、比较页、场景页、问题型文章、标准答案库 |
| 定位与话语一致性 | `GEO_A4_positioning_language` | 定位表达不清、差异化弱、话语 Token 不稳定 | 修正核心主张、RTB、禁用语、答案模板、品牌表达一致性 |
| 网站与结构化数据 | `GEO_A5_site_schema` | 官网承接弱、落地页蓝图缺口、Schema 缺失 | 建设实体页、服务页、FAQPage、Organization/Product/Service 标记、页面内链 |
| 分发与引用路径 | `GEO_A6_distribution_citations` | 信源路径不足、高频信源缺失、竞品引用占位 | 优先布局 AI 常引用的第三方页面、行业目录、评测、案例、媒体与知识库 |

---

## 4. 优先级判断标准

S9 必须给出优先级，而不是把所有建议并列展示。优先级应综合业务影响、证据强度、修复难度和对 GEO 的基础性作用。

| 优先级 | 定义 | 判断标准 |
| :--- | :--- | :--- |
| P0 | 立即处理 | 直接影响 AI 是否能识别、引用或推荐品牌；若不修复，后续内容和分发都会失效 |
| P1 | 近期处理 | 对 GEO 增长有明显作用，但依赖 P0 基础资产或需要一定执行资源 |
| P2 | 后续优化 | 对长期效率和规模化有帮助，但不是当前主要瓶颈 |

S9 必须优先处理“基础事实与实体识别”问题，其次处理“AI 可见性与高意图问答内容”，再处理“结构化数据、信源占位与分发路径”。如果 S5 显示品牌完全未被 AI 提及，或 S1/S4 缺少可验证证据，相关修复通常应被列为 P0。

---

## 5. 输出质量标准

| 输出项 | 质量标准 |
| :--- | :--- |
| 企业问题总结 | 每个问题必须有证据来源、业务影响、GEO 影响和严重程度 |
| GEO 建议 | 每条建议必须能回扣一个或多个问题，不能泛泛而谈 |
| 行动清单 | 必须使用 `GEO_A1` 至 `GEO_A6` 的 action_id 体系 |
| S5 部分样本 | 必须说明样本范围和置信度，不能因题目少或平台少否定诊断 |
| 旧模块清理 | 不得输出与 S1-S8 证据无关的固定运营板块 |
| 官网/Schema 建议 | 必须说明触发原因，并明确应由 E5 信源建设清单或外部官网改造团队承接 |

---

## 6. 建议写作口径

S9 的语言应保持策略咨询风格，重点说明企业“为什么现在需要做这些事”。建议写法应当聚焦于问题和因果链，而不是罗列任务。

推荐句式如下：

> 基于 S1 的事实资产、S4 的定位声明与 S5 的 AI 可见性诊断，当前企业的首要问题不是单纯增加内容数量，而是缺少可被 AI 稳定识别和引用的实体证据链。因此，第一优先级应是补齐实体事实、服务定义、案例证明与结构化页面，使后续问答内容和信源分发具备可引用基础。

禁止句式如下：

> 建议套用默认运营模块。

> 建议客户勾选需要的赋能板块。

> 建议做与 S1-S8 证据链无关的泛化运营动作。
