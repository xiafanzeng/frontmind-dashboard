# FrontMind 策略工作流统一输出格式标准

## 分层输出原则

FrontMind 策略工作流采用**源文件先行、品牌信息确认表汇总、单节点 PDF 后置确认**的输出原则。S1-S9 各策略分析节点只负责生成稳定、可校验、可追溯的 JSON 与 Markdown 源文件；PDF 不再作为 S1-S9 任一节点内部的完成条件，也不允许在节点内分散补齐。S10 作为最终客户确认节点，基于 S1-S9 成果与企业已填写的《应答逻辑确认表》整合生成《品牌信息确认表》XLSX（双子表），不再生成全景报告（全景报告已由其他 Workflow 负责）。S1-S9 单节点客户版 PDF 则在 S10 完成后，由 S0 询问用户是否需要额外生成；用户未回复时暂停等待，用户明确确认后才进入统一 PDF 阶段基于最终源文件批量生成。

| 格式 | 生成阶段 | 用途 | 消费者 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| **JSON (.json)** | S1-S9 节点内 | 机器可执行数据 | 下游 Agent、执行层 | 结构化数据，供程序直接消费 |
| **Markdown (.md)** | S1-S9 节点内 | 人类可读源报告 | 下游 Agent、操作者 | 作为 PDF 的唯一文本源，便于审阅与追溯 |
| **XLSX (.xlsx)** | S10 品牌信息确认表 | 客户勾改与签认 | 客户、操作者 | 双子表（品牌信息确认 + 监控问题与应答逻辑确认），遵循收集表紫色配色 |
| **PDF (.pdf)** | S10 后用户确认的统一阶段 | 客户版阅读与汇报 | 客户、管理层 | S1-S9 单节点 PDF 仅在用户明确确认后由统一脚本批量生成 |

## PDF 生成方法

S1-S9 节点内部禁止调用 PDF 生成作为完成动作。S10 输出的是《品牌信息确认表》XLSX，不再生成全景报告 PDF。S1-S9 单节点 PDF 在 S10 之后必须先询问用户；用户未回复时暂停等待。用户明确确认需要 PDF 后，才调用：

```bash
python3 S0.策略编排师.skill/scripts/unified_pdf_report_generator.py   --brand "{brand}"   --work-dir "./"   --generator "shared/geo_pdf_generator.py"   --confirmed
```

该脚本必须先检查每份 PDF 的源 Markdown 是否存在且非空，再检查关键 JSON 是否存在且可解析；任一源文件不合格时必须停止生成并打回对应节点。

## 文件命名规范

1. **品牌名前缀**：所有输出文件必须以 `{brand}_` 或 `S{N}_{brand}_` 的标准形式命名。
2. **中文命名**：文件名使用中文，便于操作者识别。
3. **格式后缀**：严格使用 `.json` / `.md` / `.xlsx` / `.csv` / `.pdf` / `.html`。
4. **无空格**：文件名中不使用空格，使用下划线 `_` 连接。

## 统一 PDF 视觉风格说明

S1-S9 单节点 PDF 由 `shared/geo_pdf_generator.py` 在 S10 后经用户确认再统一生成，采用深紫/黑/白专业风格（FrontMind 品牌标准）：

| 元素 | 规范 |
| :--- | :--- |
| 主色调 | 深紫色 `#6B21A8` 用于标题、编号标签、装饰线 |
| 表头 | 深紫色背景 `#2D1B69` + 白色文字 |
| 正文 | 黑色 `#1A1A1A`，两端对齐 |
| 引用块 | 浅紫色背景 + 紫色左边框 |
| 页眉 | 紫色分隔线 + “FrontMind 策略工作流” + “Confidential” |
| 页脚 | 页码居中 |
| 封面 | 报告标题 + 生成日期 + 保密级别 |

## 问题阶段统一枚举标准

> **重要**：全工作流（S8 SKILL.md、所有 Schema JSON、校验脚本）统一使用以下问题阶段枚举值。

| 阶段序号 | 中文名 | 英文枚举值（唯一标准） | ID 前缀 |
| :--- | :--- | :--- | :--- |
| 1 | 认知 | `awareness` | AW |
| 2 | 考虑/种草 | `consideration` | CO |
| 3 | 决策 | `decision` | DE |
| 4 | 使用 | `usage` | US |
| 5 | 推荐/倡导 | `advocacy` | AD |

## 话语 Token 命中率统一标准

| 场景 | 阈值 | 说明 |
| :--- | :--- | :--- |
| S8 策略层问答矩阵抽检 | ≥ 30%（警告线） | 策略层为 Brief 级别，允许较低命中率 |
| E2 执行层正式内容 | ≥ 70%（放行线） | 执行层为成品内容，必须高命中率 |
| E4 审查层最终校验 | ≥ 70%（放行线） | 与 E2 一致 |

## 策略-执行层交接标准

| 交接项 | 标准 | 校验方法 |
| :--- | :--- | :--- |
| 文件完整性 | S1-S9 全部源文件齐全；企业已回填的应答逻辑确认表与 S10 品牌信息确认表 XLSX 齐全；若用户确认生成 S1-S9 单节点 PDF，则统一 PDF 阶段生成的客户版 PDF 齐全；若用户跳过 PDF，则记录跳过标记并以源文件为准 | `S9/scripts/completeness_checker.py` + `S0/scripts/state_detector.py` + `S0/scripts/unified_pdf_report_generator.py` |
| 格式合规性 | JSON 可解析、MD 非空、PDF 来自统一生成阶段 | 自动化校验 |
| 品牌名一致性 | 所有文件中品牌名统一 | 文本搜索 |
| 定位一致性 | 下游文件引用的定位与 S4 一致 | 语义对比 |
| 话语一致性 | S8 答案的话语 Token 命中率 ≥ 30%（策略层标准） | `S8/scripts/token_hit_rate_checker.py` |
