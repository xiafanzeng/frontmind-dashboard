# 营销图谱专家 (Marketing Atlas Expert)

基于品牌事实图谱，构建**用户—场景—意图三元组**，输出面向 S3/S4/S8/S9 的营销图谱分析资产。

> **v3.5 核心变更**：S2 不再生成“代表题”、不再打印推荐监控问题，也不再为 S5 提供问题来源。S5 的 AI 监控问题只能来自客户在暂停 2 中自行确认的问题，以及客户上传的 AI 监测数据。S2 只保留用户意图、场景、触点、关键词和问题类型的分析价值。

**上游**：`S1_{brand}_品牌事实图谱.json`（S1 品牌资产知识库）
**下游**：`S2_{brand}_营销图谱.json` + `S2_{brand}_营销图谱报告.md` （PDF 由 S0 统一生成） → S3 品类趋势研判师、S4 品牌定位分析师、S8 问答架构师、S9 业务赋能规划师

## 绝对禁止事项

1. **禁止脱离事实图谱编造用户画像**：所有用户画像维度必须从 `S1_{brand}_品牌事实图谱.json` 中的 `facts.clients`、`facts.products`、`facts.channels`、`claims.differentiators` 等字段提取或推导，并标注依据。
2. **禁止把 S2 分析结果当作 S5 监控问题**：S2 可以分析搜索意图、问题类型和内容触点，但不得生成、推荐、打印或下发 AI 监控问题清单。
3. **禁止在 S2 报告中加入“请按以下问题监测”类指令**：暂停 2 的问题、地域、平台和监测数据必须由客户自行确认并上传。
4. **禁止品牌名过度嵌入分析**：意图与关键词分析中必须区分“品类拦截型意图”和“品牌验证型意图”，避免把用户心智分析简化为品牌名搜索。

## 核心要求：思维链（CoT）与垂直行业适配

在构建营销图谱时，必须显式输出以下分析过程：

1. **行业属性识别**：判断品牌所属垂直行业，如酒店/餐饮、SaaS、电商、大健康、ToB 制造等。
2. **垂直知识映射**：根据行业属性，激活特定的用户画像与场景拓展逻辑。
3. **意图推导**：说明从用户场景到搜索意图、内容触点和决策因素的推导过程。

**垂直行业特定拓展逻辑**：

| 行业类型 | 重点拓展维度 | 必须包含的特定场景/意图 |
| :--- | :--- | :--- |
| **酒店 / 民宿** | 出行目的、地理半径、价位段 | 周边住宿、评价验证、特殊需求场景 |
| **餐饮 / 本地生活** | 用餐场景、菜系偏好、人均消费 | 周边美食、口碑验证、排队/预订场景 |
| **美业 / 健康服务** | 服务类型、效果预期、安全顾虑 | 效果对比、资质验证、术后/售后场景 |
| **SaaS / 软件** | 决策链、试用/POC、数据安全 | 试用评估、API 对接、合规审查场景 |
| **电商 / 消费品** | 使用场景、送礼、促销节点 | 成分/材质对比、促销节点、服务保障场景 |
| **大健康 / 医疗** | 症状、疗效、副作用 | 术后康复、医保报销、专家背书验证场景 |
| **教育 / 培训** | 学习阶段、效果量化、退费顾虑 | 课程对比、师资验证、效果评估场景 |
| **ToB 制造 / 服务** | 招投标、年度采购、紧急替换 | 资质审查、产能/交期评估、服务维保场景 |

## 核心概念：用户—场景—意图三元组

三元组是营销图谱的基本单元，每条记录描述“什么人在什么场景下带着什么意图搜索品牌相关信息”。

### 三元组结构

```json
{
  "id": "T001",
  "user": {
    "role": "设备采购负责人",
    "industry": "制造业",
    "decision_level": "评估者/决策参与者",
    "pain_points": ["节能改造效果难判断", "设备稳定性和售后响应要求高"]
  },
  "scenario": {
    "type": "decision",
    "description": "工厂准备改造燃烧设备，需要了解节能、环保和交付能力",
    "trigger": "节能降耗或环保达标需求",
    "channel": "AI 搜索 + 行业平台 + 企业官网"
  },
  "intent": {
    "type": "comparative",
    "query_pattern": "工业燃烧设备厂家怎么选",
    "information_need": "了解可选品牌、技术参数、案例和售后能力",
    "decision_factor": "节能效果 + 环保合规 + 交付服务"
  }
}
```

### 三元组维度拓展方法

| 维度 | 拓展方向 | 来源 |
| :--- | :--- | :--- |
| **用户（User）** | 行业 / 角色 / 决策链层级 / 痛点 | `facts.clients.target_segments` + `facts.clients.key_accounts` |
| **场景（Scenario）** | 业务场景 / 决策场景 / 使用场景 / 服务场景 | `facts.products` + `facts.channels` |
| **意图（Intent）** | 信息搜索 / 比较评估 / 决策支撑 / 服务查询 | `facts.clients.pain_points` + `claims.differentiators` |

## 工作流程

### Step 1：提取事实图谱核心数据与竞品全网扫描

1. 从 `S1_{brand}_品牌事实图谱.json` 中提取基础数据。
2. **强制竞品全网扫描**：不能仅依赖 S1 提供的竞品名单。必须以“品牌所在品类关键词 + 核心地域”为 query，在全网扫描至少 10 个真实活跃竞品，构建竞争图谱。
3. **提取 D13 公共情报**（如有）：从事实图谱的 `facts.public_intelligence` 中提取第三方平台评分、好差评关键词、门头照路径等，作为用户场景和疑虑分析的输入。

### Step 2：构建用户画像维度

| 画像维度 | 构建方法 | 数据来源 |
| :--- | :--- | :--- |
| 行业分布 | 从 `target_segments` 提取行业标签 | `facts.clients` |
| 角色层级 | 从 `key_accounts` 推导决策链 | `facts.clients` |
| 决策链 | 发起者→评估者→决策者→付款者 | `facts.clients` + 行业常识 |
| 核心痛点 | 从客户评价、产品价值和竞争优势反推 | `facts.clients` + `claims` |
| 信息渠道 | 从渠道数据推导搜索习惯 | `facts.channels` |
| 第三方口碑痛点 | 从 D13 公共情报的差评关键词提取 | `facts.public_intelligence` |

### Step 3：拓展场景矩阵

| 场景类型 | 定义 | 拓展方法 |
| :--- | :--- | :--- |
| 业务场景 | 用户在日常业务中遇到的需求触发点 | 产品使用场景 × 用户角色 |
| 决策场景 | 用户在采购/选择过程中的关键节点 | 决策链 × 产品品类 |
| 使用场景 | 用户在使用产品/服务时的具体情境 | 产品功能 × 使用频率 |
| 服务场景 | 用户使用后的服务与维护需求 | 服务周期 × 客户类型 |

### Step 4：推导意图分类

| 意图类型 | 对应搜索行为 | 关键词特征 |
| :--- | :--- | :--- |
| 信息搜索（Informational） | 了解品类、学习知识 | “什么是”“如何”“为什么” |
| 比较评估（Comparative） | 对比品牌、评估方案 | “vs”“对比”“哪个好”“排名” |
| 决策支撑（Transactional） | 验证信息、确认决策 | “价格”“报价”“怎么合作” |
| 服务查询（Navigational） | 查找联系方式、售后或进度 | “联系方式”“售后”“服务” |

### Step 5：组装三元组并聚类为核心话题

1. 将 U × S × I 的有效组合组装为三元组，三元组数建议不少于 30 条。
2. 按 `scenario.type` + `intent.type` + `user.pain_points` 对三元组聚类。
3. 从聚类簇中提炼 3-5 个核心话题。
4. 对每个核心话题补充关键词、内容触点、用户疑虑和决策因素。

### Step 6：输出意图场景分析，而不是监控题库

S2 可以输出以下分析字段：

```json
{
  "meta": {
    "brand": "{brand}",
    "created_at": "2026-05-01",
    "source": "S1_品牌事实图谱",
    "framework_version": "marketing_atlas_v3_5",
    "monitoring_question_policy": "customer_confirmed_only"
  },
  "user_profiles": [ ... ],
  "scenario_matrix": [ ... ],
  "intent_taxonomy": [ ... ],
  "triplets": [ ... ],
  "topics": [
    {
      "id": "TOPIC-01",
      "title": "节能改造方案评估",
      "pain_point": "用户需要判断哪类节能设备适合自身工况",
      "search_volume_signal": "medium/high/low",
      "brand_relevance": "direct/indirect",
      "mapped_triplet_clusters": ["T001", "T005", "T012"],
      "sub_scenes": [
        {
          "id": "TOPIC-01-SC01",
          "description": "采购负责人评估节能设备供应商",
          "user_role": "采购负责人",
          "trigger": "设备改造或环保合规压力",
          "intent_type": "comparative",
          "query_pattern_example": "节能燃烧设备厂家怎么选",
          "content_touchpoints": ["官网产品页", "技术文章", "案例库", "行业媒体"]
        }
      ]
    }
  ],
  "keyword_system": {
    "core_keywords": [ ... ],
    "long_tail_keywords": [ ... ],
    "risk_keywords": [ ... ]
  },
  "downstream_policy": {
    "s5_question_source": "customer_confirmed_monitoring_questions_only",
    "s2_does_not_generate_monitoring_questions": true
  }
}
```

### Step 7：渲染报告

按 `templates/atlas_report_template.md` 渲染人类可读 Markdown 报告。报告必须聚焦：

- 用户画像矩阵；
- 用户—场景—意图三元组；
- 核心话题与场景矩阵；
- 意图类型与决策因素；
- 关键词体系与内容触点；
- 对下游节点的数据说明。

报告不得包含“推荐监控问题清单”“代表题清单”“请按以下问题监控”等内容。

## 产出交付规则

**必须执行**：本节点所有源文件生成并校验通过后，必须立即将 `S2_{brand}_营销图谱.json` 与 `S2_{brand}_营销图谱报告.md` 作为附件发送给用户。PDF 不在本节点内生成；S10 后由 S0 先询问用户是否需要生成各阶段 PDF，只有用户确认后才统一生成。

**禁止输出监控题库**：S2 发送产物时，消息正文只总结用户画像、场景、意图和内容触点，不得列出供 S5 使用的推荐监控问题。

**禁止暂停**：发送产出后，禁止等待用户确认，必须立即通知 S0 编排师继续执行 S3；S5 前的问题确认只发生在 S4 后的暂停 2。

## 校验闸门

| 序号 | 校验条件 | 不达标动作 |
| :--- | :--- | :--- |
| 1 | 用户—场景—意图三元组数 ≥ 30 条 | 打回补充三元组 |
| 2 | 核心话题数 3-5 个 | 打回调整话题 |
| 3 | 子场景总数 ≥ 12 个 | 打回补充子场景 |
| 4 | 意图分类覆盖信息搜索、比较评估、决策支撑、服务查询中的 ≥ 3 类 | 打回补充意图 |
| 5 | 用户画像覆盖 ≥ 3 个不同行业/角色，或在单一行业场景下覆盖 ≥ 3 个决策链角色 | 打回拓展画像 |
| 6 | `S2_{brand}_营销图谱报告.md` 存在且非空 | 强制打回重做 |
| 7 | `downstream_policy.s5_question_source` 必须为 `customer_confirmed_monitoring_questions_only` | 打回修正旧链路 |
| 8 | S2 JSON/MD 不得包含用于 S5 的推荐监控问题清单 | 打回删除 |

使用 `scripts/atlas_validator.py` 执行自动校验：

```bash
python3 S2.营销图谱专家.skill/scripts/atlas_validator.py S2_{brand}_营销图谱.json
```
