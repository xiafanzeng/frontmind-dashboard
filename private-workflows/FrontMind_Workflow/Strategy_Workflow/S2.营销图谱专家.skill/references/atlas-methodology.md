# 营销图谱方法论：用户—场景—意图三元组建模

本文档详细说明营销图谱的核心建模方法——用户—场景—意图三元组（User-Scenario-Intent Triplet），包括理论基础、建模步骤、质量标准和常见陷阱。

---

## 一、理论基础

### 1.1 为什么用三元组

传统关键词研究只关注"搜什么"，忽略了"谁在搜"和"在什么情境下搜"。三元组模型将搜索行为还原为完整的用户决策情境，使品牌能够针对具体场景提供精准内容。

在 AI 搜索（GEO）时代，AI 平台不再简单匹配关键词，而是理解用户意图并生成综合答案。三元组模型恰好与 AI 的意图理解机制对齐：

| 传统 SEO | GEO 三元组 |
| :--- | :--- |
| 关键词 → 页面 | 意图 → 场景化答案 |
| 单一维度匹配 | 多维度语义理解 |
| 页面排名 | AI 答案引用 |

### 1.2 三元组的数学定义

一个三元组 T = (U, S, I)，其中：
- U（User）：用户画像向量，包含行业、角色、决策层级、痛点等维度
- S（Scenario）：场景向量，包含场景类型、触发条件、渠道等维度
- I（Intent）：意图向量，包含意图类型、查询模式、信息需求等维度

三元组的总数 = |U| × |S| × |I| 的有效子集（排除不合理组合）。

## 二、建模步骤

### Step 1：用户画像构建

从品牌事实图谱的 `facts.clients` 中提取用户画像的基础数据，然后按以下维度拓展：

**维度一：行业分布**
从 `target_segments` 提取目标行业，按营收贡献排序。每个行业至少构建 1 个典型用户画像。

**维度二：角色层级**
在每个行业中，识别决策链上的关键角色：
- 发起者（Initiator）：提出需求的人
- 评估者（Evaluator）：技术评估和方案对比的人
- 决策者（Decider）：最终拍板的人
- 使用者（User）：实际使用产品/服务的人
- 付款者（Payer）：负责付款和合同的人

**维度三：痛点矩阵**
交叉行业和角色，识别每个组合的核心痛点。痛点来源：
- 客户评价中的高频关键词
- 竞品劣势的反面
- 行业通用痛点

### Step 2：场景矩阵拓展

将用户画像与产品/服务交叉，拓展四类场景：

**业务场景**：用户在日常业务中遇到的需求触发点
- 构建方法：产品使用场景 × 用户角色
- 示例：环保局项目负责人需要年度监测数据 → 触发检测服务采购

**决策场景**：用户在采购决策过程中的关键节点
- 构建方法：决策链阶段 × 产品品类
- 示例：技术评估人员对比三家检测机构的资质和价格

**使用场景**：用户在使用产品/服务时的具体情境
- 构建方法：产品功能 × 使用频率
- 示例：工厂环保专员每月提交检测报告给环保局

**服务场景**：用户在使用产品/服务后的服务与维护需求
- 构建方法：服务周期 × 客户类型
- 示例：年度框架合同客户的续约评估

### Step 3：意图分类与映射

将场景映射到四类搜索意图，每类意图有不同的关键词特征和内容需求：

| 意图类型 | 搜索行为 | 关键词特征 | 内容需求 |
| :--- | :--- | :--- | :--- |
| Informational | 了解品类 | "什么是"、"如何" | 教育型内容 |
| Comparative | 对比品牌 | "vs"、"对比"、"排名" | 对比型内容 |
| Transactional | 确认决策 | "价格"、"报价" | 转化型内容 |
| Navigational | 查找品牌 | 品牌名、联系方式 | 品牌型内容 |

### Step 4：三元组组装与去重

将 U × S × I 的有效组合组装为三元组，然后去重：
- 合并高度相似的三元组（用户角色相同、场景类似、意图一致）
- 保留差异化最大的组合
- 确保最终三元组数 ≥ 30

## 三、质量标准

| 维度 | 标准 | 检查方法 |
| :--- | :--- | :--- |
| 覆盖度 | 三元组覆盖所有目标行业 | 行业标签去重计数 |
| 均衡度 | 四类意图各占 15%-35% | 意图类型分布统计 |
| 可操作性 | 每个三元组可推导出具体内容主题 | 人工审查 |
| 数据溯源 | 每个三元组可追溯到事实图谱的具体字段 | 字段引用检查 |

---

## 四、常见陷阱

| 陷阱 | 表现 | 修正方法 |
| :--- | :--- | :--- |
| 画像同质化 | 所有用户画像只有行业不同，角色和痛点雷同 | 增加决策链维度 |
| 场景空泛 | 场景描述过于笼统，无法推导具体内容 | 增加触发条件和渠道 |
| 意图偏移 | 意图与场景不匹配 | 重新审查映射关系 |
| 数量堆砌 | 三元组数量达标但质量低 | 去重后补充高质量三元组 |

## 五、三元组聚类与场景树衔接（v3.0 新增）

三元组建模完成后，需要将三元组**聚类为核心话题**，作为场景树问题架构的输入。

### 5.1 聚类方法

按以下维度对三元组进行分组聚类：

| 聚类维度 | 权重 | 说明 |
| :--- | :--- | :--- |
| `scenario.type` | 高 | 相同场景类型的三元组优先聚合 |
| `intent.type` | 高 | 相同意图类型的三元组优先聚合 |
| `user.pain_points` | 中 | 共享痛点的三元组倾向于归入同一话题 |
| `scenario.trigger` | 低 | 相同触发条件作为辅助聚类信号 |

### 5.2 聚类产出

每个聚类簇对应一个**核心话题（Topic）**，话题的属性从簇内三元组中提炼：

```
话题标题 = 簇内三元组的共性场景描述
话题痛点 = 簇内三元组的共性用户痛点
话题搜索量信号 = 用搜索工具验证的真实搜索热度
```

### 5.3 与场景树的数据流

```
三元组（≥30）→ 聚类 → 核心话题（3-5）→ 子场景拓展 → 变体生成 → 场景树
```

详细的场景树构建规则见 `references/two-layer-question-framework.md`（v3.0）。
