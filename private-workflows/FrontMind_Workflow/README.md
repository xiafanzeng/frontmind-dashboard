## 三、快速开始

1. **上传本 ZIP** 到 Manus 对话
2. Agent 自动读取 `00.FrontMind总控路由.skill/SKILL.md`
3. 选择进入 **策略层**（选 1）或 **执行层**（选 2）
4. 执行层启动时除策略层成果 zip 整包外，必须上传企业提交图片库；图片库无需内置 `image_library_manifest.json`，E0 自动扫描并生成 manifest/索引；随后跟随 5 个全局暂停/确认点完成全流程。

## 三点五、执行层新增必需输入：企业提交图片库

进入执行层时必须同时上传：

```text
S0_{brand}_strategy_pack_v{N}.zip   （策略层成果整包：含 strategy_pack.json 与 S1-S9 全部源文件）
Client_Submitted_Image_Library.zip 或 client_submitted_image_library/
```

> 执行层主输入已由单个 strategy_pack.json 升级为**策略层成果 zip 整包**：E0 先解包→校验引用文件真实存在→建立源文件索引，并强制 E1/E2 在撰写 A1/C1b 前逐个真实读取对应 S 节点全文，避免只传 json 导致内容丢失。

该图片库只需提交 ZIP 或目录，不再要求包含 `image_library_manifest.json`，也不再要求单独确认图片库 manifest。E0 会自动扫描图片，生成标准化 manifest、图片库校验报告和检索索引。后续 E1-E5 所有企业实图、证书图、团队图、案例图、产品图、门店/环境图都必须引用该图片库的 asset_id；缺图时输出补图需求，不得用网图或 AIGC 冒充企业实图。

## 五、5 个全局暂停/确认点

| 暂停编号 | 所属层 | 时机 | 用户动作 |
| :--- | :--- | :--- | :--- |
| 暂停 1 | 策略层 | S1 完成后 | 确认品牌事实图谱 |
| 暂停 2 | 策略层 | S4 完成后、S5 前 | 确认 AI 监控问题、地域/平台，并上传 AI 可见性监测数据 |
| 暂停 3 | 策略层 | S9 完成后、S10 前 | 回填《应答逻辑确认表》（企业现场讨论），作为 S10 子表2 数据源 |

> 此外 E5 后另有「继续生产确认」（仅决定是否继续制作更多文章/类型），不属于事实/方案审批类暂停，不计入全局编号。

## 七、合并说明

本合并版遵循以下原则：

1. **优化版优先**：总控版本中已优化的 SKILL.md（S0、S9、E0、E5）替换原始版本，确保跨层契约修复和命名空间统一已生效。
2. **子文件完整保留**：每个 Skill 的 `references/`、`templates/`、`scripts/` 子目录完整保留原始内容，不做删减。
3. **全局契约权威**：`Master_Control/FrontMind_Master_Control.md` 作为 SSOT（Single Source of Truth），所有 Agent 的 SKILL.md 在涉及跨层交互时以此为准。
4. **路径已更新**：总控路由中的路径引用已更新为合并后的 `Strategy_Workflow/` 和 `Execution_Workflow/` 前缀。

## S10 品牌信息确认表（替代旧全景报告）

策略层不再生成全景报告（全景报告已由其他 Workflow 完成）。在暂停3 企业回填《应答逻辑确认表》后，S0 调用 S10 整合 S1-S9 全部成果与应答逻辑表，生成 `S10_{brand}_品牌信息确认表.xlsx`——含两个子表：子表1「品牌信息确认」（完整复刻品牌信息收集表的 13 个区段，含企业填写/修改高亮列）、子表2「监控问题与应答逻辑确认」（逐条承接应答逻辑，含企业想修改高亮列）。表格遵循品牌信息收集表的紫色配色风格。

该确认表交企业做**暂停4 最终确认**：企业在高亮列回填修改意见（留空＝确认无误）。S0 用 `confirmation_diff_parser.py` 解析回填，得到结构化《品牌信息修改清单》并按 `affected_nodes` 逐项重新调用受影响的 S1-S9 节点回灌（方案 A），复核一致后才封装最终 strategy_pack 交执行层，确保交付内容与企业最终确认一致。
